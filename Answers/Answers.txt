2. Explain memory management in Java (Heap, Stack, GC).

In short: Heap stores objects, Stack stores method calls and local variables, and GC automatically cleans up unreachable objects from the heap.

5. Explain the SOLID principles.

Ans. 

Definition: SOLID principles are five design principles in Java that help us write clean, maintainable, reusable, and flexible code. They make software easier to understand, test, and modify.

S – Single Responsibility Principle: A class should have only one responsibility, meaning it should have only one main reason to change.

O – Open/Closed Principle: A class should be open for extension but closed for modification. We should be able to add new features without changing existing code unnecessarily.

L – Liskov Substitution Principle: A child class should be able to replace its parent class without breaking the program.

I – Interface Segregation Principle: A class should not be forced to implement methods it does not need. It is better to create small, specific interfaces.

D – Dependency Inversion Principle: High-level classes should depend on abstractions (interfaces), not directly on low-level classes (concrete implementations).

In short: SOLID principles help developers write code that is easy to maintain, extend, reuse, and test.

8. What is Deadlock in Java? How can we prevent it?
Ans. 

1. Definition
Deadlock is a situation where two or more threads wait for each other to release resources, and none of them can continue execution.

2. How it works internally
Thread 1 locks Resource A and waits for Resource B.

Thread 2 locks Resource B and waits for Resource A.

Both threads wait forever.

This situation is called Deadlock.

Example :

public class Main {
    public static void main(String[] args) {

        final Object A = new Object();
        final Object B = new Object();

        Thread t1 = new Thread(() -> {
            synchronized (A) {
                synchronized (B) {
                    System.out.println("Thread 1");
                }
            }
        });

        Thread t2 = new Thread(() -> {
            synchronized (B) {
                synchronized (A) {
                    System.out.println("Thread 2");
                }
            }
        });

        t1.start();
        t2.start();
    }
}

One-line interview answer:

"Deadlock in Java occurs when two or more threads wait for each other to release locks, so none can proceed. We can prevent it by acquiring locks in a fixed order, avoiding nested locks, and using tryLock() with timeout."

13. How does HashMap work internally in Java?
Ans.

1. Definition
HashMap is a class in Java that stores data in Key-Value pairs.

Keys must be unique.

Values can be duplicated.

It allows one null key and multiple null values.

It does not maintain insertion order.

2. How it works internally
When we insert a key-value pair, HashMap calculates the hash code of the key.

It uses the hash to find the bucket (index).

The key-value pair is stored in that bucket.

If two keys have the same bucket index, a collision occurs.

Java handles collisions using a linked list or a balanced tree (when required).

While retrieving data, HashMap uses the key's hash and equals() method to find the correct value.


 Code Example

java
import java.util.*;

public class Main {
    public static void main(String[] args) {

        HashMap<Integer, String> map = new HashMap<>();

        map.put(1, "Rahul");
        map.put(2, "Amit");
        map.put(3, "Priya");

        System.out.println(map.get(2));
    }
}


Output: Amit

One-line interview answer:

"HashMap internally uses an array of buckets. It calculates the hash code of a key to find the bucket and uses equals() to identify the correct key. If collisions occur, it handles them using Linked Lists or Balanced Trees."

 1. How does Spring Dependency Injection work internally?
Ans. 

Definition: Dependency Injection (DI) is a feature of Spring in which the Spring container creates objects and provides them with the objects they depend on, instead of creating those objects manually.

How it works internally: When a Spring application starts, the IoC container reads the configuration and identifies the beans using annotations such as `@Component`, `@Service`, and `@Repository`, or through `@Bean` methods. After dependency injection, Spring manages the bean lifecycle and makes the beans available wherever they are needed.

In short: Spring DI works by identifying beans, creating objects, injecting their dependencies, and managing their lifecycle through the IoC container.


 2. Difference between @Component, @Service, @Repository, and @Controller.
Ans. 

Definition: @Component, @Service, @Repository, and @Controller are Spring annotations used to mark classes as Spring-managed beans. Spring detects these classes through component scanning and manages their objects.

Difference: @Component is a general-purpose annotation used for any Spring-managed class. @Service is used for the service layer, where business logic is written. @Repository is used for the data access layer, where database operations are performed, and it also supports translating persistence exceptions into Spring's data access exceptions. @Controller is used in the presentation layer to handle web requests and return views. In REST APIs, @RestController is commonly used to return data directly, such as JSON.

In short: @Component is general, @Service handles business logic, @Repository handles database operations, and @Controller handles web requests.

3. What is the Spring Bean lifecycle?
Ans. 

Definition: The Spring Bean lifecycle is the process through which Spring creates, initializes, manages, and destroys a bean (object) inside the Spring IoC container.

How it works: First, Spring creates the bean object. Then, it injects the required dependencies. After that, Spring performs initialization callbacks, such as `@PostConstruct`, to execute setup logic. The bean is then ready to be used by the application. When the Spring container shuts down, Spring calls the destruction callback, such as `@PreDestroy`, to perform cleanup operations.

In short: The Spring Bean lifecycle consists of bean creation, dependency injection, initialization, usage, and destruction.

4. What is the use of @Transactional? What are the pitfalls?
Ans. 

Definition: @Transactional is a Spring annotation used to manage database transactions automatically. It ensures that a group of database operations is treated as a single unit of work. If all operations succeed, the transaction is committed; if a failure occurs, the transaction can be rolled back.

How it works: When we apply @Transactional to a method, Spring starts a transaction before the method executes. If the method completes successfully, Spring commits the transaction. If a configured rollback exception occurs (by default, unchecked exceptions such as RuntimeException), Spring rolls back the transaction.

In short: @Transactional ensures database consistency by providing automatic commit and rollback functionality. However, we should be careful about self-invocation, exception handling, transaction propagation, and long-running transactions.

10. What is the difference between @Autowired, @Qualifier, and @Primary?
Ans. 

Definition: @Autowired, @Qualifier, and @Primary are Spring annotations used for Dependency Injection. They help Spring identify which bean should be injected into a class when creating objects and resolving dependencies.

How they work:

@Autowired: It is used to inject dependencies automatically. Spring searches for a matching bean in the IoC container and injects it into the required class. By default, it resolves dependencies primarily by type.

Example:



@Service
public class EmployeeService {

    @Autowired
    private EmployeeRepository employeeRepository;

}
Here, Spring automatically injects the EmployeeRepository bean into EmployeeService.

@Qualifier: It is used when multiple beans of the same type are available in the Spring container. It helps us specify exactly which bean should be injected.

Example:



@Component("emailService")
public class EmailService implements MessageService {
}

@Component("smsService")
public class SmsService implements MessageService {
}

@Service
public class NotificationService {

    @Autowired
    @Qualifier("emailService")
    private MessageService messageService;

}
Here, two beans implement the same interface. Using @Qualifier("emailService"), we tell Spring to inject the EmailService bean.

@Primary: It is used when multiple beans of the same type are available. It tells Spring which bean should be preferred by default when no specific @Qualifier is provided.

Example:


@Component
@Primary
public class EmailService implements MessageService {
}

@Component
public class SmsService implements MessageService {
}

@Service
public class NotificationService {

    @Autowired
    private MessageService messageService;

}
Here, Spring injects EmailService by default because it is marked with @Primary.

Interview Tip: @Autowired is used for automatic dependency injection, @Qualifier is used to resolve ambiguity by specifying a bean name, and @Primary is used to define the default bean when multiple beans of the same type exist.

Important: If both @Primary and @Qualifier are used for the same injection point, @Qualifier takes precedence over @Primary. Also, constructor injection is generally preferred over field injection in modern Spring Boot applications.

Definition: Filter, Interceptor, and AOP are mechanisms used in Spring Boot to handle cross-cutting concerns such as logging, authentication, authorization, request validation, and performance monitoring. However, they work at different levels of the application.

How they work:

1. Filter: A Filter is part of the Java Servlet API. It works at the servlet container level and intercepts incoming HTTP requests and outgoing HTTP responses before they reach the DispatcherServlet or after they leave it.

It is commonly used for:

Authentication and security checks.

Request and response logging.

CORS handling.

Request and response modification.

Example:



@Component
public class MyFilter implements Filter {

    @Override
    public void doFilter(
            ServletRequest request,
            ServletResponse response,
            FilterChain chain)
            throws IOException, ServletException {

        System.out.println("Before Request");

        chain.doFilter(request, response);

        System.out.println("After Request");
    }
}
Here, chain.doFilter() passes the request to the next filter or servlet in the chain.

2. Interceptor: An Interceptor is provided by the Spring MVC framework. It works around the Controller execution and intercepts requests after they reach the DispatcherServlet but before they reach the Controller.

It provides three important methods:

preHandle(): Executes before the Controller method.

postHandle(): Executes after the Controller method but before the response is rendered.

afterCompletion(): Executes after request processing is completed.

It is commonly used for:

Controller-level logging.

Checking user permissions.

Measuring request execution time.

Tracking API requests.

Example:



@Component
public class MyInterceptor implements HandlerInterceptor {

    @Override
    public boolean preHandle(
            HttpServletRequest request,
            HttpServletResponse response,
            Object handler) {

        System.out.println("Before Controller");
        return true;
    }

    @Override
    public void afterCompletion(
            HttpServletRequest request,
            HttpServletResponse response,
            Object handler,
            Exception ex) {

        System.out.println("After Request Completion");
    }
}
We also need to register the interceptor using WebMvcConfigurer.

3. AOP (Aspect-Oriented Programming): AOP is a programming technique provided by Spring that helps us separate cross-cutting concerns from business logic. It works at the method execution level using concepts like Aspect, Advice, Pointcut, and JoinPoint.

It is commonly used for:

Method-level logging.

Performance monitoring.

Transaction management.

Auditing.

Exception handling around method execution.

Example:



@Aspect
@Component
public class LoggingAspect {

    @Before("execution(* com.example.service.*.*(..))")
    public void logBefore() {
        System.out.println("Before Service Method");
    }

    @After("execution(* com.example.service.*.*(..))")
    public void logAfter() {
        System.out.println("After Service Method");
    }
}
Here, @Before executes before the matched service method, and @After executes after it completes, whether normally or exceptionally.


Interview Tip: Remember the main difference:

Filter: Works at the Servlet level.

Interceptor: Works at the Spring MVC Controller level.

AOP: Works at the method execution level.

For example, if we want to log every incoming HTTP request, we can use Filter. If we want to check something before a Controller executes, we can use Interceptor. If we want to log the execution time of service methods, we can use AOP.

Important: Spring Security primarily uses Servlet Filters through its security filter chain. Also, Spring AOP generally works through proxies, so self-invocation (calling another advised method within the same object) does not trigger the advice in the usual proxy-based configuration.

Definition: Spring Security is a security framework provided by Spring that helps protect applications from unauthorized access. It provides authentication and authorization mechanisms to secure REST APIs and web applications.

Authentication: It verifies who the user is.

Authorization: It checks what the authenticated user is allowed to access.

Spring Security internally uses a chain of Servlet Filters called SecurityFilterChain to intercept incoming HTTP requests and apply security checks before allowing requests to reach the Controller.


Interview Tip: Remember the most important internal flow:

SecurityFilterChain → AuthenticationManager → AuthenticationProvider → UserDetailsService → SecurityContextHolder → Authorization

Spring Security uses a filter-based architecture. It intercepts incoming requests, authenticates users, stores authentication information in the SecurityContext, and checks permissions before allowing access to protected resources.

Important:

Passwords should never be stored in plain text. Use BCryptPasswordEncoder or another suitable password encoder.

HTTP 401 means authentication is required or has failed.

HTTP 403 means the user is authenticated but does not have sufficient permissions.

In JWT-based authentication, a security filter typically validates the JWT and establishes authentication in the SecurityContext for each request.


18. What is JWT authentication, and how do you implement it in Spring Boot?
Ans. 

Definition: JWT (JSON Web Token) is a token-based authentication mechanism used to securely transmit information between a client and a server. It is commonly used in Spring Boot microservices and REST APIs to authenticate users without maintaining traditional server-side HTTP sessions.

When a user successfully logs in, the server generates a JWT token and sends it to the client. The client stores the token and sends it with every subsequent request. The server validates the token before allowing access to protected APIs.

JWT Structure
A JWT consists of three parts separated by dots (.).


text
Header.Payload.Signature


Interview Tip: JWT authentication works on a token-based mechanism. First, the user logs in and Spring Security validates the credentials. Then the server generates a signed JWT token. The client sends this token with every subsequent request using the Authorization: Bearer header. A JWT filter validates the token and sets the authentication inside SecurityContextHolder, after which Spring Security performs authorization.

Important:

Always use HTTPS to protect JWT tokens during transmission.

Keep signing keys secure and never hardcode them in source code.

Use short-lived access tokens and an appropriate refresh-token strategy.

JWT authentication is stateless, but token revocation requires additional mechanisms such as token denylisting or short expiration periods.

Spring Security also provides built-in OAuth2 Resource Server support for validating JWTs, so writing a custom JWT filter is not always necessary.

 1. How does Hibernate manage caching (1st level vs 2nd level)?
Ans. 
Definition: Hibernate caching is a mechanism used to improve application performance by reducing repeated database queries. Hibernate provides two levels of caching: First-Level Cache and Second-Level Cache.

How it works:

First-Level Cache (L1 Cache): It is enabled by default in Hibernate and is associated with the Session object. When we fetch an entity for the first time, Hibernate stores it in the session cache. If we fetch the same entity again within the same session, Hibernate returns it from the cache instead of querying the database.

Second-Level Cache (L2 Cache): It is associated with the SessionFactory and shared across multiple Hibernate sessions. It is not enabled by default and requires a cache provider such as Ehcache or Infinispan. When an entity is fetched, Hibernate can store it in the second-level cache so that other sessions can reuse it without querying the database.

Advantages of Hibernate Caching:

Reduces database queries.

Improves application performance.

Reduces database load.

Improves response time for frequently accessed data.

In short: First-Level Cache is associated with a Hibernate Session and is enabled by default, whereas Second-Level Cache is associated with SessionFactory, shared across sessions, and requires explicit configuration. Both caches help reduce database calls and improve application performance.
